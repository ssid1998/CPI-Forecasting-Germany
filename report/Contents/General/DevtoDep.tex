\chapter{Development to Deployment}

\section{Data Structure}

The CPI forecasting project passes several artifact types from development into deployment. The workflow begins with the raw CSV export from Destatis, converts it into a cleaned \texttt{pandas} dataframe, uses that dataframe to train forecasting models, and then produces serialized model objects, plots, and evaluation tables. This staged transformation is important because the Streamlit application does not retrain the models; it consumes outputs already generated during development.

\section{Tools}

The main tools used in this transition are Python, \texttt{pandas}, \texttt{statsmodels}, \texttt{scikit-learn}, \texttt{joblib}, \texttt{matplotlib}, \texttt{plotly}, and \texttt{streamlit}. Each tool has a specific role: data handling, model estimation, evaluation, serialization, visualization, and deployment. LaTeX then documents the resulting workflow and findings in report form.

\section{File Structure for Model Exchange}

The model handoff between development and deployment is organized through \texttt{Code/saved\_models/}. During development, \texttt{Code/src/modeling\_pipeline.py} trains ARIMA, ETS, and SARIMA and writes their fitted wrappers to disk with deterministic filenames. During deployment, \texttt{Code/app.py} reads these files again with \texttt{joblib.load()} and uses them to generate forecasts without refitting the models.

The relevant filenames are:

\begin{itemize}
	\item \texttt{ARIMA\_1\_1\_1.joblib}
	\item \texttt{ETS\_A\_A\_A.joblib}
	\item \texttt{SARIMA\_1\_1\_1x1\_1\_1\_12.joblib}
\end{itemize}

\section{Description of the File Types}

The project uses several file types in the development-to-deployment transition:

\begin{itemize}
	\item \textbf{CSV} for the raw CPI input data.
	\item \textbf{PNG} for exported plots such as decomposition and forecast comparison figures.
	\item \textbf{JOBLIB} for serialized trained model objects.
	\item \textbf{PY} for executable pipeline and dashboard code.
	\item \textbf{TEX} for report documentation and academic presentation.
\end{itemize}

\section{Saving Models}

After fitting each model, the modeling pipeline serializes it with \texttt{joblib.dump()}. This is a key transition step because it preserves the trained model state and makes it available to the dashboard layer. Without serialization, the app would need to refit the models every time it starts, which would be inefficient and would blur the separation between development and deployment.

\section{Loading Models}

The deployment side reverses this process. \texttt{Code/app.py} maps the user-selected model name to a filename, loads the corresponding object from \texttt{Code/saved\_models/}, and uses it to generate predictions and confidence intervals. If a file is missing, the app reports the issue to the user instead of silently failing.

The dashboard allows users to select a forecasting model, adjust the confidence interval level, and inspect both forecast curves and evaluation metrics interactively.
